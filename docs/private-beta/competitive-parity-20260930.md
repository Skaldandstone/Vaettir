# Competitive workflow benchmark, September 30, 2026

## Scope and evidence boundary

Official vendor documentation reviewed September 30, 2026, against Vaettir source at `29352e2` plus separately owned in-progress connector work. This is a bounded benchmark of nine relevant products, not an exhaustive market census or a declaration of parity. No competitor paid tenant was opened, so documented UI behavior is not hands-on usability acceptance. Editions and add-ons differ. No customer repository, paid AI call, invitation, deployment, or production mutation was performed for this audit.

Current Vaettir tickets were read: SSE-135 (P9-00 integration foundation), SSE-127 (platform), SSE-131 (execution), SSE-133 (readiness/reporting), SSE-136 (hardening), SSE-137 (imports). Source/runtime evidence, not an old checked checklist, determines acceptance. Main coordinator owns updates to those tickets and the shared local handoff.

The immediate production sign-in/project/owner-permission incident takes precedence over feature breadth. A product with extensive reports but unreliable workspace access is not production-ready.

## Five prioritized changes and verification

These are implementation candidates, not completed work. Deploy only independently passing slices and keep the access incident first.

1. **Restore trustworthy access and permission states (SSE-136/SSE-127).** Trace sign-in through session token, API availability and membership lookup. Distinguish loading/error from a verified non-admin role. Verify signed-out redirect, signed-in owner, editor and viewer in browser; expired session, API failure and cross-tenant denial in integration tests. Do not repair by granting a role based on an email string or bypassing authorization.
2. **Persist reusable case views and align export scope (SSE-127/SSE-133).** Save a named typed filter/sort definition per project/user; offer all, filtered or selected export with the count visible. Start with existing supported fields, not a free-form SQL field. Verify refresh/reopen, two users, two tenants, unknown/deleted fields, special characters, empty results, selected IDs outside the project and CSV formula escaping. Export must match the visible query exactly.
3. **Make editing stay in context and orderable (SSE-127).** Open edit in the same resizable drawer/modal, preserve current view/selection, render numbered action/data/result columns and keyboard Move up/down controls; drag is an enhancement, not the only input method. Verify cancel/no write, validation retains edits, save refreshes only the changed row, concurrent edits reject stale writes, narrow viewport and focus return. Treat per-step media and persistent suite ordering as additional data-model work, not superficial UI switches.
4. **Add a focused report center using existing evidence (SSE-133).** First templates: case inventory, run results and requirement coverage. Wizard: report question, scope, preview/export. Every report states source/as-of time, filters and denominators and drills to matching records. Verify no-run/unlinked/blocked/skipped cases, multi-run duplicates, archive policy, two tenants, print layout and CSV totals. Scheduled delivery and customizable dashboards are subsequent increments unless fully implemented/tested.
5. **Replace metadata-only connection with a verified picker (SSE-135/P9-00).** Provider chip opens internal setup screens, starts real authorization in the provider window, returns verified identity and searchable repository multi-select, then scope review. Offer hosted/self-hosted hostname selection where supported. Verify state/PKCE, session binding, revoked/expired credentials, popup blocked/closed, retries, redirect allowlist, SSRF/private-address denial, pagination and cross-tenant callback replay. No source fetch or paid AI until separate processing approval; missing provider app setup is an honest unavailable state.

## Follow-on parity backlog, not overnight guarantees

- Tenant-safe custom-field definitions and query builder with explicit AND/OR, saved shared/private views, server-side pagination and stable ordering.
- Durable suite moves and manual ordering with keyboard alternative, safe concurrent updates and undo.
- Per-step attachments/results, stable case-version snapshots in runs, parameterized execution and run-scoped dependencies.
- Bulk risk/type/design review queue with preview, balance, admin credit request, cancellation, partial recovery and one-charge idempotency.
- Report scheduling, recipient permissions, redaction, historical reproducibility and configurable dashboards with consistent drill-down.
- Full native connector portfolio and expiry/refresh/revoke UX. Git/Perforce/SVN identity models are not interchangeable.

## Release gate

Source tests and documented competitor features do not prove deployed usability or complete feature parity. Required evidence: isolated database regressions, tenant/permission tests, production build, rendered desktop/mobile and keyboard smoke, immutable deployed revision/digest, healthy service rollout, authenticated read-only acceptance. External provider acceptance, customer-source processing, paid model output and actual email delivery must be identified separately. Do not claim "better than all competitors" without comparative user testing.
