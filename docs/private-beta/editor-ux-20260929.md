# Editor UX checkpoint, September 29

## Source implemented

- Project population opens in a same-page modal with internal evidence screens; setup state remains mounted when navigating between screens.
- Human-readable role labels; sortable current-member and pending-invitation tables, search and confirmed bulk role/seat changes using existing server authorization and last-owner checks. Partial failures remain selected.
- Test-case column sorting; redundant suite column removed; suite links select the sidebar location.
- Resizable details drawer with keyboard resizing, wrapping draft actions, compact metadata and numbered Given/When/Then columns directly below Suite. Scenario phases remain distinct; no artificial action/result pairing is inferred.
- Automation drafts persist before successful responses. Existing drafts return without another charge. A partial unique database index prevents concurrent active generations. Explicit rejection retains the historical output and actor/time. Viewers can read but cannot reject; editor/full-seat checks protect generation/rejection.
- Multiple repository metadata registrations with provider/revision identity. Registration is explicitly NOT authentication, discovery or proof of deployment. Existing scan connectivity remains separate.

## Evidence

- Disposable PostgreSQL migration/seed succeeded with both additive migrations.
- API: 376 tests passed, including retained-draft replay, explicit rejection, cross-case rejection denial, viewer denial and concurrent generation charging once with a mocked AI provider.
- Web: 41 tests passed. Root typecheck: seven tasks passed; final touched UI typecheck repeated. Focused changed-component ESLint passed.
- Synthetic rendered drawer: keyboard resize, steps immediately below suite, long-filename wrapping, draft retained on reopen and cancelled rejection. Found and corrected a CSS class collision that constrained content to 320px. Synthetic fixtures are not provider or production acceptance.

## Not complete

Persistent drag ordering and moving between suites; prerequisite case graph and same-run gating; inline metadata editing; per-step image/video storage; imported-source document retention/linking; durable bulk risk/type analysis with credit preview/admin approval; risk-derived priority suggestions preserving manual overrides; native connected-source wizard discovery and reconciliation. Repository registration does not close provider integration acceptance.

Previously generated, browser-only drafts cannot be reconstructed from absent stored data. New successful generations are retained; an interrupted process before persistence needs operator reconciliation, not an automatic second charge.

Deployment identity and runtime acceptance must be recorded separately after rollout. No main merge is implied.
