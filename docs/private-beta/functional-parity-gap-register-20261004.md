## Quality intelligence beyond adding charts

Every displayed metric needs a defined population, time interval, release/configuration scope, input provenance, missing-data behavior and a route to inspect the contributing evidence. New capabilities should distinguish:

- Risk-weighted requirement coverage from the number of cases in the repository.
- Executed coverage from planned, blocked, skipped and unrecorded work.
- New regression, repeated failure, reopened defect and environment/test defect.
- Defect escape, detection/removal effectiveness and time to verified repair from task-status changes alone.
- Observed execution and maintenance cost from an automation label or an AI estimate.
- Recorded qualified review from ordinary editable approval metadata.

Exploratory session charters, notes, findings and conversion already exist in source. Stable case IDs, version comparison/restore, independent prerequisites, paid-draft retention and durable bulk analysis are also existing work, not discoveries to rebuild. Verify their complete ordinary-user task and production delivery rather than counting features twice.

## Improvement standard

Functional improvement means a user finishes the same scoped task with fewer repeated entries or navigation steps, retains original evidence, recovers safely from interruption and can act on a supported recommendation. The existing acceptance contract specifies equivalent tasks. No vendor workflow was exercised under equivalent conditions tonight, so there is no measured superiority claim. Tonight's new source must pass its morning validation before it becomes accepted functionality.
