# Node and Brotli runtime repair

CVE-2026-111497 affects the Brotli decoder, including the copy embedded in Node.js. An operating-system image scan does not cover Node's embedded library. A successful application build or a web image with no scanner findings therefore does not establish that this issue is fixed.

The repair uses the official Linux x64 Node 22.23.4 archive. Its archive, binary, license, signed checksum list and detached signature are pinned. The checksum signature must verify against the separately pinned existing Node release key before that binary executes. The final runtime verifies the actual executable bytes and rejects the upstream malformed stream through both synchronous and byte-stream decoding. An ordinary synthetic round trip must still succeed.

Debian's `brotli_1.1.0-2` source and packaging are retained. Its signature and archive hashes are checked before applying only upstream commit `da9806362874b9bd4b552a3af360b5d6347beb12`. The package is honestly labeled `1.1.0-2+vaettir1`; the upstream version is not fabricated. The build requires the actual packaged decoder to reject the malformed stream with error `-17`, the unpatched control to fail that regression with its specific diagnostic, all discovered native CMake tests to pass, and all three libraries' SONAMEs, public exports, data/TLS sizes and loader dependencies to match the original Debian libraries. This is a regression comparison, not a claim to have reproduced exploitation.

The isolated CI build receives only public source inputs and synthetic fixtures. The complete 67-file upstream test corpus is separately pinned to the original source commit and verified before tests; Debian's reduced corpus is not treated as the full suite. Corpus bodies remain in the build stage. The exported proof contains the signed Node executable and license, the Debian runtime package, source and signature records, test results and binary/ABI identities. Application and native proof identity must be reconciled against the selected committed source before release. The API installs the backport and repeats its native browser, graphics, Prisma, Git, shell, image-processing and Mesa checks. The web runtime receives only the signed Node replacement and repeats its final startup and image checks.

Any scanner finding against the custom Debian version remains unsuppressed. A component disposition requires the complete actual final-image inventory, installed package status and exact binary correspondence to the independently reviewed patch/build/test proof. No blanket vulnerability waiver, alternative credential, tenant activation or change to customer approval controls is granted by this repair.

Source and CI proof are separate from final image security review, compatible migrations, rollback, service stabilization and authenticated hosted acceptance. Those release gates remain required. Mobile native publishing and aTwist directory activation remain pending their existing reviews.

Primary references: [Node security advisory](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases), [Node 22.23.4 release](https://nodejs.org/en/blog/release/v22.23.4/), [Node release keys](https://github.com/nodejs/release-keys), [Debian tracker](https://security-tracker.debian.org/tracker/CVE-2026-111497), [Brotli fix](https://github.com/google/brotli/commit/da9806362874b9bd4b552a3af360b5d6347beb12).
