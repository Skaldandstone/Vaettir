## Migration and concurrency review

- The three additive execution-history foreign-key lookup indexes use ordinary `CREATE INDEX`. Before production application, review actual table sizes and the write-lock window. A disposable migration passing does not approve a live lock window.
- The manual-step DELETE guard now validates the old transition table once per statement, locks distinct manual runs deterministically, then performs a separate fresh head lookup. Original INSERT/UPDATE protections remain.
- A nonempty manual DELETE under Repeatable Read or Serializable deliberately fails closed with SQLSTATE `40001`; fixed snapshots could otherwise miss a newly committed protected observation. Empty and CI-only deletes remain supported. Read Committed is the supported manual-erasure path.
- Raw concurrent direct SQL can still produce a deadlock refusal through tuple/run lock ordering. The guard promises atomic refusal and evidence protection, not contention-free operation or unrestricted deletion.
