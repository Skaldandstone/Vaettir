# Test-management and connector increment (September 30)

## Source changes

- The shared project-creation and project-population wizard uses a bounded in-page modal. Its content scrolls separately from persistent Back, Save and Continue controls. Source choices are pressed-state chips; missing required project fields get a visible message and focus target. Desktop and 375px rendered fixture checks covered navigation, validation and overflow.
- GitHub joins GitLab in the provider-native authorization flow: actor-bound one-use OAuth state with PKCE, encrypted credential storage, account verification, bounded repository listing, reviewed multi-selection and explicit disconnect. GitHub's OAuth `repo` grant is broader than the selected project links (it can read and write repositories); the UI discloses that distinction. Explicit GitHub disconnect requires upstream token revocation confirmation before Vaettir clears local credentials and links. A failed revocation leaves the connection intact; if GitHub has already revoked the token but the local transaction failed, retry first checks GitHub's documented invalid-token response before completing local cleanup. The production OAuth application is not configured or live-accepted; no client repository source was fetched.
- Test cases have persisted suite placement, within-suite ordering and prerequisite links. Manual execution checks prerequisite results before recording a dependent result. Existing imported cases are reconciled against the previous import snapshot: unchanged reruns do not duplicate or rewrite, source changes do not overwrite human edits, and missing baselines become review conflicts. Imports are bounded and atomic. Rows without stable external IDs still cannot be reliably deduplicated.
- Selected cases can be queued for bounded risk, type or test-design review with a cost/balance preview, explicit approval and an admin credit-use request path. Saved risk suggestions remain accessible. A risk assessment result uses a compare-and-swap on the original case and risk fields so edits made during provider work are not overwritten. No paid AI or customer records were changed for validation.
- A second source-only slice adds risk-derived priority suggestions with explicit acceptance or a reasoned high/critical business override; neither path silently changes an existing priority. The decision and audit are atomic, and stale case editors cannot overwrite a newer decision. Credit-use request decisions and audit entries are also atomic; an admin's acceptance is a request receipt, not a credit grant.
- Case steps support case-scoped image/video references with per-step display and editor controls. The additive migration preserves existing steps. Attachment ownership/type checks, a step revision compare-and-swap, and a deletion guard prevent cross-case links, concurrent overwrite and dangling references. The import baseline includes media references so an import cannot silently erase a human addition. Existing attachment uploads are limited to 25 MB; this is not a video transcoding or streaming service.
- Project reports can preview, save and apply typed case filters from the existing per-user saved views. The filtered case inventory is bounded to 20,000 records and calculated in a repeatable-read snapshot; execution and requirement figures remain project-wide and are labeled separately. CSV export escapes spreadsheet formulas. This is not arbitrary SQL, a cross-entity query builder, or scheduled reporting.
