# Test-management and connector increment (September 30)

## Source changes

- The shared project-creation and project-population wizard uses a bounded in-page modal. Its content scrolls separately from persistent Back, Save and Continue controls. Source choices are pressed-state chips; missing required project fields get a visible message and focus target. Desktop and 375px rendered fixture checks covered navigation, validation and overflow.
- GitHub joins GitLab in the provider-native authorization flow: actor-bound one-use OAuth state with PKCE, encrypted credential storage, account verification, bounded repository listing, reviewed multi-selection and explicit disconnect. GitHub's OAuth `repo` grant is broader than the selected project links (it can read and write repositories); the UI discloses that distinction. Explicit GitHub disconnect requires upstream token revocation confirmation before Vaettir clears local credentials and links. A failed revocation leaves the connection intact for retry. The production OAuth application is not configured or live-accepted; no client repository source was fetched.
- Test cases have persisted suite placement, within-suite ordering and prerequisite links. Manual execution checks prerequisite results before recording a dependent result. Existing imported cases are reconciled against the previous import snapshot: unchanged reruns do not duplicate or rewrite, source changes do not overwrite human edits, and missing baselines become review conflicts. Imports are bounded and atomic. Rows without stable external IDs still cannot be reliably deduplicated.
- Selected cases can be queued for bounded risk, type or test-design review with a cost/balance preview, explicit approval and an admin credit-use request path. Saved risk suggestions remain accessible. A risk assessment result uses a compare-and-swap on the original case and risk fields so edits made during provider work are not overwritten. No paid AI or customer records were changed for validation.
