# Final application release successor v1

Source handback for Main's independent review. The source lane does not run any
build, Docker/native/archive operator, database, cloud, device, provider, customer
or hosted action. Source tests use synthetic bytes/delegates only. No source file
or generated manifest grants execution authority or full release acceptance.

`production-native-successor-v1` at reviewed `8b7d9f0` is immutable. This package
imports its admission, complete-inventory, transaction-ledger, native/consumer,
NSS and byte-link mechanisms. `policy.json` pins all ten raw source files and
the original bbd helper/runtime/materializer manifests. Seventeen retained bbd
operator files under `inherited/` are **inert derivation inputs**. Never run them
directly: they retain historical110/no-native-change paths and identities.
The directory-local Git attributes disable newline conversion for this package;
raw and Git payload bytes must match, including the frozen derivation inputs.

Main supplies the final main commit/tree, normal merge and full CI receipts.
`NORMAL_MERGED_REPAIR` must identify PR111, its actual two parents/head/tree, a
proof tree and final-source ancestry. No pending PR head is embedded here.
`nativeBindings` is the fully populated native8b contract, including all110 old
migration hashes plus111, privacy/source ledger, exact main CI, compatible
immutable recovery targets, revocation-preserving schema111 recovery, baseline
full-content trees and the separately reviewed NSS fixture. Main's pending-final
bindings remain a useful input draft; null gates stay null until real evidence.

## What is executable source

1. `build-context.mjs`: prepares exact Git blob source files and a concrete
   network-disabled application compilation recipe on an independently admitted
   existing toolchain/cache image. It performs no build. The new workspace is
   `/vaettir-final-build`; the reviewed cache image must prove that path absent
   and cover the exact final lockfile's offline dependency closure. Commands keep
   frozen-lockfile installation, Prisma generation/check and the real turbo app
   build. Web reuses the actual parent static tree/manifest and the final source's
   finite retention helper. The output target is scratch compiled evidence.
   Exact Git100755 members receive individual COPY --chmod=0755 instructions,
   preserving executable transport from Windows without a blanket permission change.
2. `context.mjs prepare`: composes the real independently reviewed SQLite
   transaction stage **by immutable FROM digest**, then installs only the exact
   reviewed application-output file ledger via `apply-application.mjs`. It never
   copies a fabricated dpkg database or repeats the package install. Inputs are
   read-only internal BuildKit mounts; the applicator is not shipped. API's
   absent USER and Web's nextjs USER are preserved. Parent command/entrypoint
   are inherited; source labels and release identity are exact.
3. `derive_operators.py`: produces separately reviewed executable materializer
   and actual-runtime probes from the hash-pinned original sources. Replacement
   cardinality and syntax are checked before output. Original source/diffs are
   retained. The complete archive/TAR/blob/hash/size/DiffID verifier and exact
   pull/load/export/inspect custody remain. Layer counts come from exact current
   custody and manifest/config, bounded by128 and inherited archive budgets,
   not the obsolete API98/Web56 assumption. No Docker login/helper replay: the
   inherited one-use0600 exact-registry auth file/disposal remains.
4. `native-probe-context.mjs`: prepares actual final-image diagnostic source.
   It does not run it. The final immutable app image is the diagnostic FROM;
   SQLite installed/consumer checks, browser and Prisma checks run offline.
   API also binds the exact reviewed u4 certutil/fixture internally read-only at
   its original `/run/vaettir-nss` path. The fixture's original fixed output
   `/vaettir-sqlite-observation-v1` is preserved. No fixture text substitution,
   host sharing change, installation or shipping of certutil is involved.
   The final target is scratch evidence only. `run-native.cjs` retains child
   status/code/errno/syscall/signal and raw stdout/stderr. Its exit0 preserves
   failure evidence; `error:null`/all original outcomes plus independent image,
   mount, raw loader and real-store proof are mandatory, never build status alone.
5. Generated API42 and normal/disabled/unknown probes retain original prestart
   ownership, internal network, no host ports/mounts, limits, actual stdin,
   timeout, seven workers, no restart/OOM and catalog/draft invariance checks.
   The retained synthetic110 seed is restored into **new owned databases**, then
   `migrate_fixture.py` runs the actual candidate's packaged Prisma migration
   once and verifies111. It does not relabel a110 restore as111. No old fixture
   network or database is reused. New names contain the final source identity.
6. Generated `probe-additional-runtime.py` runs separately source-reviewed
   actual compiled-module plugin, Android and import probes on new synthetic
   databases, minimum6/5/2 assertions respectively, no skips or DB/RPC mocks.
   Their exact final-source scripts and review receipts are deliberately absent
   from the template. Main must provide them; existing host tests do not replace
   final-image execution. The inherited Web23 controller/network/image admission
   is retained and requires separate reviewed controller derivation.
7. `seal-runtime.mjs` links complete immutable images, API42/three modes/7workers,
   Web23, added route logs and schema111 recovery into a runtime proof index.
   It is not an ECS deployer or release approver. Hosted/provider/device/owner
   acceptance and current Web-first/API-second rollout gates remain explicit.

## Main's receipt shapes and ordering

All references are `{path,sha256,bytes}`, rooted at one explicit evidence root;
no symlinks, traversal, unchecked absolute paths or silent normalization.
`accepted()` requires `accepted:true`, `independentReview:true`, an exact scope
and a nonempty retained proof tree which is rehashed. These are **inputs from
Main**, never emitted as acceptance by this package.

`COMPLETE_IMMUTABLE_IMAGE` binds `image`, raw `manifest`, `config`, compressed and
uncompressed ordered `layers`, same-daemon `observations`, actual `archive`, full
`verification`, complete `inventory`, ordered `layerOrder`, `filesystemReview`
and proof tree. The filesystem review scope is
`COMPLETE_FILESYSTEM_AND_EXTENDED_METADATA`, binding image digest, inventory and
layer-order hashes, actual parser source and whiteout/extended-metadata evidence.
The byte-link helper still does not claim full TAR/materialization acceptance.

`TRANSACTION_STAGE_CUSTODY` binds the actual observation/review hashes to the
preserved immutable stage and its full inventory plus normalized snapshot.
The original install count, successful raw commands and exact changed-file
categories are checked again. Complete inventory JSON is limited to256MiB;
the two-snapshot transaction is separately bounded to512MiB. Other JSON retains
64MiB. An input exceeding a bound requires source review, never automatic retry.

`FINAL_APPLICATION_BUILD_OUTPUT` binds final source/tree, actual source archive,
original build log, exact compiled payload manifest and source-reviewed
normalizer, native inventory, stage inventory, before/after snapshots and ledger.
The ledger scope is `FINAL_APPLICATION_OVERLAY`; every changed path has one
explicit category. `/app` changes cannot alter any native row/inode alias.
Only exact successful-observer paths can be removed; the staged native regression
probe can be removed only at its exact path/hash. There is no recursive wildcard
delete. The applicator supports regular single-link files, directories and
confined relative symlinks with explicit metadata; unexpected hardlinks/special
files/setuid/extended metadata refuse and need independent successor review.
The required `/app/.vaettir-final-application.json` marker is a new hash-bound
payload file with final source/tree. Observer inputs/output must be absent from
the final full-content inventory. Additional native files cannot be hidden in an
application exception. Root must retain/inspect the actual generated image delta.

`THREE_COHORT_STATIC_RETENTION` binds current final source plus the parent's first
two cohorts, exact normalized file hashes/sizes and actual resulting static tree.
Missing/extra assets, cross-cohort collisions and changed historical bytes refuse.
Retain the raw helper manifest and its normalization source in the proof tree.

`FINAL_NATIVE_STRUCTURE` binds all old native tuples except exact accepted SQLite
and optional exact proof binary, genuine package/status/trigger/loader evidence,
complete consumer and dynamic-symbol closure. `FINAL_COMPONENT_CONTENT` binds
source/tree/digest/configDigest, native audit, exact actual filesystem and scan.
`UNSUPPRESSED_FINAL_IMAGE_SCAN` retains every raw finding and exact disposition;
only an independently reviewed matching `EXISTING_SCOPED_FINDING` can carry
forward. No new security waiver, prefix/count relaxation or fake package metadata.

Order deliberately avoids circular gates: structural native/filesystem/scan
review precedes materialization; full same-daemon content precedes diagnostics;
actual final-image NSS/browser/Prisma review precedes API/Web/PG application
probes. `nativeRuntime` uses the frozen8b `finalNativeEvidence` schema including
raw tool/fixture/loader/store refs and exact image identity. A new native result
must not be replaced with the standalone builder proof or native parent proof.

```text
node build-context.mjs BINDINGS EVIDENCE_ROOT SOURCE_REPO api NEW_BUILD_CONTEXT
node context.mjs prepare BINDINGS EVIDENCE_ROOT SOURCE_REPO api NEW_APP_CONTEXT

```

Repeat separately for Web. Main must independently review/hash each generated
context and exact actual build request before a once-only build. No build/start
or upload permission is created here. Reuse Main's reviewed existing cloud
transport/start/collection mechanisms, with new exact generated input review;
never execute the old bbd prepare-inputs/cloud scripts against changed inputs.
API compute remains inherited SMALL without a compute override.

`operator-configuration.template.json` fixes SOURCE_REPO, evidence root, receipt
directory, new release root under SOURCE_REPO/.local/releases, historical root,
source package and base bindings ref. Generated `prepare_release.py` validates
the already retained source archive member-by-member against exact Git blobs,
including modes, private-path exclusions and finite aggregate bounds. It creates
the new release root exclusively only after source/CI and archive validation.
It writes `prepared.json` binding `commit`, `tree`, `migrationCount:111`,
`newMigrationCount:1`, `sourceArchiveSha256`, `bindingsSha256`, and
`releaseAccepted:false`. The exact source.zip is retained. No provisional
prepared receipt is supplied by this source handback.

Before generated operators run, Main supplies
`generated-operators-source-acceptance.json` binding generated-manifest and exact
configuration hashes; `paired-materialization-source-acceptance.json` binds the
generated source-manifest and final source; the runtime counterpart binds
runtime-manifest/source. Web additionally binds the exact probe source and

Later inputs go into new `materialize-bindings.json`, `native-bindings.json`,
`runtime-bindings.json` and corresponding `*-input-acceptance.json` receipts
binding exact bytes, source and original base-bindings hash. Base native source,

phase still independently validates all evidence and its immutable image.

Only Main runs generated prepare_release.py, materialize-local.py api/web, native diagnostics,
prepare-image-isolated-fixture.py, probe-normal-recovery-runtime.py,

SOURCE_REPO NEW_INDEX` writes the proof index exclusively. It retains false
release/hosted/production acceptance; it does not execute rollout or approval.

No deployment entrypoint is supplied. Main's current backup/disabled-six-schedule/

launch blocker; directory activation remains separately pending review.
